## Checked and clean

- **Dead code / commented-out code:** none (`tsc` runs with `noUnusedLocals`/`noUnusedParameters`; manual read of every source file).
- **TODO / FIXME / placeholder text:** none (grep).
- **Dependencies:** each one is imported. `@hashgraph/sdk` (keys, `Cache` drift, HCS-1 transactions), `standards-sdk` (HCS-10/11), `zod` (state, decisions, envelopes), `dotenv` (root `.env`), `server-only` (keeps the SDK out of the client bundle). No UI library, no state library, no wallet stack.
- **Tests:** 60, none tautological. None mocks the behaviour it claims to prove. Mirror Node _responses_ are faked to test interpretation (spoofed payer, wrong memo owner, tampered profile, lag, 404 vs 5xx). Every Hedera _write_ is proven on testnet instead (`docs/testnet-proof.json`, re-verified by `check:eligibility`).
- **Comments:** only where they explain _why_: SDK quirks, standard rules, the clock-drift fix, the 700-byte cap. No narration of what the next line does.
- **README:** every command in it was run; costs and timings are measured values (59s registration; 0.92–1.56 HBAR setup; 0.0057 HBAR per decision).

## Kept on purpose

- `scripts/check-eligibility.mjs` ships to scaffolded projects. It doubles as a conformance check for anyone who forks this into their own template.
- `reports/` and `docs/RESEARCH_NOTES.md` ship too. They record why the template deviates from the SDK's default path (dead registry endpoint, broken inscription service), which a maintainer needs when the SDK changes.
- `hcs10.ts` parses the `connectionId` memo field, which only tests read today. It completes the HCS-10 memo grammar rather than parsing half of it.
